# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

@AGENTS.md

PoVoiceHud is an always-on-top WinUI 3 HUD (not a web app): it transcribes what is said with Whisper and fact-checks each claim as it goes, highlighting the sentence green or red. `README.md` is the one document: use, settings, files, and how it works with the design decisions behind it. `docs/manual-test.md` is the checklist for what tests cannot reach.

## Repo facts

- The only branch is `master`.
- `master` tracks `origin` on GitHub (`punkouter26/PoVoiceHud`), where CI builds and tests every push; push after committing.
- `src/PoVoiceHud.Core` holds everything testable (audio, VAD, ASR, the fact checker, view models) and never references WinUI. `src/PoVoiceHud.App` is the XAML shell. `tests/PoVoiceHud.Core.Tests` is xUnit v3 on Microsoft.Testing.Platform.
- Build output is in `artifacts/`, not `bin/` and `obj/`.
- Warnings are errors, with analyzers at `latest-recommended`. Rules that are switched off are listed with their reason in `.editorconfig`; add to that list rather than suppressing inline.

## Commands

```powershell
dotnet build PoVoiceHud.sln
dotnet test --solution PoVoiceHud.sln                                      # everything, about 10 s
dotnet test --project tests/PoVoiceHud.Core.Tests -- --filter-class "*FactCheckerTests"   # one class
dotnet run --project src/PoVoiceHud.App                                    # the real app: opens the microphone
dotnet run --project src/PoVoiceHud.App -- --demo                          # a sample conversation, no audio (Debug)
dotnet run --project src/PoVoiceHud.App -- --demo --facts                  # the same, on the Facts page (Debug)
dotnet run --project src/PoVoiceHud.App -- --demo --code                   # the same, on the Code facts page (Debug)
dotnet run --project src/PoVoiceHud.App -- --demo --history                # the History page, read from the real session log (Debug)
dotnet run --project src/PoVoiceHud.App -- --demo --compact                # the header alone (Debug)
dotnet run --project src/PoVoiceHud.App -- --demo --scripted               # real routing, checker and code answerer; canned model, this repo (Debug)
dotnet run --project src/PoVoiceHud.App -- --demo --screen                 # the same, on the Screen facts page (Debug)
dotnet run --project src/PoVoiceHud.App -- --demo --settings               # the Settings page, no audio (Debug)
dotnet run --project src/PoVoiceHud.App -- --demo --setup                  # the first-run page, no audio (Debug)
pwsh build/pack.ps1                                                        # Setup.exe + update packages in artifacts/releases (Velopack)
```

## How a sentence becomes a highlight

- **Pipeline** (`HudPipeline`): audio frames → `SileroVad` + `UtteranceSegmenter` → Whisper → `Sentences` (one line each, stamped with the clock time) → `FactChecker`. Transcription and checking are two separate channel stages, and up to `ParallelChecks` (3) claims are checked at once, so a slow model call never delays the next line. Each check gets the two sentences heard before it as context, checked or not. `Checking` says when a line is queued for the checker and when it is done; `Verdicts` carries each verdict with its line. A `FactCheckUnavailableException` becomes one status ("Fact checks paused: …"), not a verdict per line. Muting increments a generation counter; work already in flight is thrown away when it finishes. `Checker` can be replaced while it runs.
- **FactChecker**: `IsCandidate` (generous: three words, numbers count, not only fillers, not a plain question; question words are shared with the code answerer in `SpokenText`) → evidence (`EvidenceSources.For`: Wikipedia, Wikidata, and GDELT news for a claim about now, at once, each best-effort within 2.5 s) → `FoundryClient` (the schema puts claim, reason and source before the verdict, then a 0–1 confidence) → a verdict with the claim restated to stand alone, or null for `not_a_claim`. The prompt carries today's date. A claim about now ("current", "still"…) keeps a verdict only with a looked-up article (the model's knowledge ends in mid-2024). The cache key includes the context when the claim says "it", "they" and so on. A model that cannot be asked throws `FactCheckUnavailableException` (`NeedsSetup` for a refused key or missing deployment); the content filter refusing one sentence is a "can't tell". `Connection.TestAsync` is the one-call check used by Apply and at start. `FoundryClient.Model` is fixed (`gpt-4.1-mini`) and the reply is held to a JSON schema (kept as a JSON string constant); every client counts its calls, time, tokens, retries and failures into the one `ModelStats` the app owns.
- **Words**: the `Verdict` enum keeps the model's terms (Supported, Contradicted, Unverified); everything a person reads uses `Verdict.Label()`: Correct, Incorrect, Can't tell.
- **View models**: `HudViewModel` holds `Live` (`LiveLineViewModel`: Heard → Checking → Correct / Incorrect / CantTell) and `Facts` (`FactViewModel`, correct and incorrect only, newest first, repeats counted), and `CodeFacts` (`CodeFactViewModel`: answers and code verdicts with their files), `ScreenFacts` (verdicts with `Insight.OnScreen`, which stay off Facts) under `ScreenNow` (the latest screen description), and which page shows: `Page` (Live, Facts, Code, Screen, History) or Settings (`IsSettingsOpen`, or `NeedsSetup` until a working endpoint and key exist). A code answer puts the line in `Answered`. `ShownFacts`/`ShownCodeFacts`/`ShownScreenFacts` are the lists narrowed by `FilterText` and `FilterKind` (kept in step with `Mirror`, not rebuilt), and are what the pages list and copy. `Names` (`SpeakerNames`) renames You and Them; rows are told on a rename rather than subscribing. `Trend` feeds the header's sparkline, `Arrived` raises a `Cue`, `IsCompact` shrinks the window to its header, and `History` (`HistoryViewModel`) reads days back from `SessionLog`, sums one up with `SessionSummarizer` and exports it with `SessionExport`. The window is a standard one (resizable, kept on top) with the header drawn into the title bar; the pages fill it.
- **Wiring** is all in `ServiceCollectionExtensions.AddPoVoiceHudCore`; `CreateChecker` builds the fact checker on its own too.
- **Code repository** (`Repos/`, optional): `RepoSource` clones a GitHub or Azure DevOps URL into `%LOCALAPPDATA%\PoVoiceHud\repos` (LibGit2Sharp, token from `CredentialStore.RepoToken` as the password) or reads a folder, `Probe`s it for Apply, and builds web `Link`s to files. `CodeRepository` keeps a `SymbolIndex` (tracked files, EF entities) and the files' text fresh with a file watcher, and finds excerpts: `Named` (files a sentence names, via `SymbolMatcher`) and `Search` (best text matches); `Editor` builds `vscode://file/…:line` links. `CodeAnswerer.IsAbout` routes a sentence to the code (repository name via `SymbolMatcher.Says`, a named file, or code words such as "our website"), and `AskAsync` returns a `CodeFact` (answer, or verdict for a statement; a sentence ending in "?", a request, or a question word followed by an asking verb ("which model does our app use.") always gets an answer) using `FoundryClient` with `CodeAnswerer.ReplyFormat` (evidence and reason before the verdict; a verdict whose evidence is neither a path sent nor a quote of 12+ characters from an excerpt becomes Unverified). The pipeline sends those sentences there (questions too) and publishes `CodeFacts`; it also feeds Whisper's vocabulary. `Settings.Repository` may hold several, one per line (`RepoSource.Locations`); the container has them as `CodeRepositories`, `CodeAnswerer.Pick` chooses one per sentence, and a fact names its repository only when there are several. A saved file is read again on its own; a commit, a new or deleted file, or a migration snapshot rebuilds the index; search caches which files hold each word until the files change. `App.StartAsync` opens the repositories before building the container; `CreateCodeAnswerer` is swapped in with the checker.
- **Settings changes**: Settings is a page with Apply and Cancel (`SettingsViewModel`); Apply tests a new endpoint or key with one call before saving, and leaving the page without Apply reverts it. Without a working endpoint and key the app shows only Settings and never opens the microphone; `StartAsync` also tests the connection and goes back to setup if the key is refused. `App.ApplyAsync` then starts the pipeline after setup, swaps in a new checker when a pipeline is running and the repository and its token are unchanged (the microphone and the call are always both captured), and otherwise disposes the whole DI container and builds a new one. A run counter stops a slower, older start from installing its pipeline. The state is `settings.json`, Credential Manager (`CredentialStore`) and the session log with its `{date}-summary.md` files; for secrets, follow the existing Credential Manager pattern. *Listen only during calls* (`CallsOnly`) polls `CallDetector` (active capture sessions of known call apps) every 3 s, and `App.Listen` mutes the pipeline while there is no call without touching the mute button.
- **JSON**: settings, the session log and the window placement go through the source-generated `CoreJson`; prompts are built from `JsonObject`s. `PoVoiceHud.Core` has `IsAotCompatible` on, so reflection-based JSON fails the build. `Settings` keeps plain setters, not `init`: the generated reader fills every init property, so a missing key would lose its default.
- **Screen** (`Screen/`, optional, `Settings.WatchScreen`): `ScreenWatcher` captures the monitor holding the foreground window every 3 s (`ScreenCapture`, GDI), and only when `ScreenShot.Differs` says it changed sends a JPEG to `FoundryClient` (`IVisionModel`) for a short description. `HudPipeline.Screen.Current` goes with every check as `screen` (`IFactChecker.CheckAsync`, `CodeAnswerer.AskAsync`); a verdict read off it has source "screen", is exempt from the about-now rule, reads "On screen: …" and has `Insight.OnScreen`, so it goes to Screen facts. `Screens` feeds the session log. Swapped with the checker; paused while muted. While it is on, the App excludes the HUD window from capture (`CaptureExclusion`).
- **Feedback**: `SoundPalette` cues (each ≤ 240 ms, under the segmenter's 300 ms floor; an answer has its own) at the *Cue volume*, a `BrushTransition` on the highlight, the newest Live line sliding in (composition), the level bars breathing while checking, and a red wash on the header for an incorrect claim, all under the one *Sounds and animations* switch. There are no shaders or particle effects.

## Checking a UI change

The app is a desktop window, so the browser tools cannot drive it. Use the `--demo` forms above and capture the window (`PrintWindow` with `PW_RENDERFULLCONTENT` works without focus); do not send synthetic keys or clicks to the desktop, because the owner is usually working on it. A `--demo` run does not save its window placement. Running without `--demo` opens the microphone and appends what it hears to `%LOCALAPPDATA%\PoVoiceHud\sessions`.

## Limits worth knowing

- 100 unit tests and 50 integration tests at most (`[Trait("Category", "Integration")]` marks the latter). The suite is at 75 and 23.
- Native AOT for the app needs Visual Studio's C++ build tools for the linker; they are not on the owner's machine.
